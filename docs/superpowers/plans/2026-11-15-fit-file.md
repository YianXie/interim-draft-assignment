# Fit File Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The page reads an optional, office-checked `fit.xlsx` (facts a local model found in teachers' written answers), uses it as the last tie-break in the draft while keeping everyone else where they were, and shows it on the teacher panel and in the download; a separate reader script writes that file using Ollama.

**Architecture:** `fit.xlsx` is read in `src/import.js` like last year's optional files and lands on each teacher as `t.fit`, with `school.fit = true`. `src/solver.js` builds the plain draft exactly as today, then adds two stages: most teachers on a course they fit, then most teachers on their plain-draft course. The reader is a Node CLI in `tools/reader/` that reuses `src/import.js` and `src/xlsx.js` and talks to Ollama over HTTP; the page never calls a model.

**Tech Stack:** Plain JavaScript (ES modules), esbuild, HiGHS 1.15.4, hucre via `src/xlsx.js`, `node:test`, Playwright, Python + OR-Tools for `tools/expected.py` only.

**Spec:** `docs/superpowers/specs/2026-11-15-fit-file-design.md` (read it first), within `docs/spec.md`.

## Global Constraints

- Invented data only. Never open `~/interim-private` or any real file; fixtures come from the existing invented school.
- No existing check may be loosened or edited. Every existing unit and browser test passes unchanged; `fixtures/expected.json` (`[1, 1654, 5]`), `fixtures/expected-past.json` and every file in `fixtures/school/` and `fixtures/past/` stay byte for byte as they are.
- With no `fit.xlsx` added, nothing behaves differently from today.
- Budgets from `seed/measure.cjs` apply: Start uses `first` (at most 80 words, 30 outside `data-rows`), an opened teacher uses `detail` (at most 60 panel words). Nothing under 15 px.
- Forbidden words (`tests/e2e/words.mjs`) stay absent from every screen and workbook.
- With names off, no Quote and no Fact text from `fit.xlsx` appears in the DOM (text and attributes) or in the downloaded workbook.
- The page's Content-Security-Policy is unchanged; the page makes no outside request.
- Screen copy: rename or remove, never add a sentence beyond the lines this plan fixes.
- Work on branch `fit-file`, cut from `main`. Merging is the owner's call (visible freeze Fri 20 Nov 2026).
- "Done" means the pasted output of `npm run check` ending `CHECK OK`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A `fit.xlsx` whose rows can't change anything** (only Limitation rows, only blank Course Codes, or fits on courses the teacher can't be placed on): the draft must equal the plain draft exactly. Test in Task 3.
2. **The same fact twice, or two facts on one course:** counts as one fit. Test in Task 3.
3. **Reload after building with `fit.xlsx`:** the fit line still shows with no re-upload, because it lives in the saved upload record. Test in Task 5.
4. **An office edit with extra spaces around an email or code** (`" INT-02 "`, `" Ann.Lee@fernhollow.example"`): accepted, the way the six files trim. Test in Task 1.
5. **`fit.xlsx` dropped alone, before the six:** its row shows "ready" or its problem, and Build stays locked until the six are ready. Test in Task 5.

An unreadable reply is asked once more; still unreadable puts the email in `notRead`.
- Produces: `node tools/reader.mjs --dir <folder with the six> [--out fit.xlsx] [--host http://127.0.0.1:11434] [--model qwen3.5:9b] [--prompt tools/reader-test/prompt_v3.txt]`.
